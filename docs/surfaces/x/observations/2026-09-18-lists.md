## Direct observations

### Lists management request family

The Lists page used the standard X GraphQL family:

`https://x.com/i/api/graphql/{queryId}/ListsManagementPageTimeline`

Observed details:

- method: `GET`;
- operation: `ListsManagementPageTimeline`;
- observed query ID: `XfmuvArU-jDYCIrF2BdN1A`;
- status: HTTP 200;
- query parameters: `variables` and `features`;
- no `fieldToggles` parameter was present;
- request variables contained only `count`;
- observed requested `count`: 100;
- no `userId` variable was present.

The absence of `userId` plus the viewer-scoped response root strongly indicates that this management surface is scoped to the authenticated viewer. That interpretation is inference from the directly observed wire shape.

The query ID is a dated observation, not a durable constant.

### Response envelope

The data response used:

`data.viewer.list_management_timeline.timeline.instructions`

Observed instruction types:

- `TimelineClearCache`;
- `TimelineTerminateTimeline(direction=Top)`;
- `TimelineTerminateTimeline(direction=Bottom)`;
- `TimelineAddEntries`.

The AddEntries instruction contained:

- one `TimelineTimelineModule` headed **Discover new Lists**;
- one `TimelineTimelineModule` headed **Your Lists**;
- one Bottom `TimelineTimelineCursor`.

The response therefore separates recommendation/discovery material from the operator's own/subscribed list collection at the timeline-module level.

No follow-up `ListsManagementPageTimeline` request was generated.

### Partial GraphQL error behavior

This capture provided the first directly observed partial-success GraphQL response in R2.

The HTTP response status was 200 and the usable Lists data was present, while the top-level GraphQL response also carried `errors[]`.

The two observed errors were structurally:

- code: 214;
- name: `BadRequestError`;
- kind: `Validation`;
- source: `Client`;
- message class: a Strato serialization/decode failure;
- paths targeted the nested `default_banner_media_results.result` field of list items.

The affected optional banner-media subfield failed while the surrounding list objects and management timeline remained usable.

This yields an important parser rule:

**GraphQL `errors[]` is not equivalent to total response failure.**

A Sociarium reader must preserve successful `data` while recording field-level errors/provenance, rather than discarding the whole response whenever `errors` is non-empty.
